# Full-viewport workspace — October 14, 2026

The initial root URL and `#home` load immediately into the compact Welcome window with the room and BMW/Bloom satellites. There is no opening veil or fade on Welcome or the satellites. The existing welcome-sound action is sound-only.

Following a portfolio link, dock app, or project satellite opens the selected app edge-to-edge across the browser viewport. Direct non-Home deep links also open full-size. This is a full-viewport application surface, without the browser Fullscreen API or an OS permission prompt. Expand/Restore toggles the active window between full-size and its compact, movable size. Recenter restores compact windows. Closing a secondary window returns to compact Welcome; closing a project returns to full-size Work.

The full-size surface is opaque. Status collapses into a centered 128×28px island with a 152×44px interactive target. Clicking it reveals identity, availability, Luke, local time, and decorative battery. The dock auto-hides while reading. Pointer proximity to the bottom edge reveals it; leaving the edge/dock hides it after a short crossing allowance. Touch users tap the bottom handle and dismiss by choosing an app or tapping outside. Keyboard users activate the handle to focus Home, Tab through navigation, and use Escape to return to content. Hidden controls are inert and excluded from keyboard navigation.

The content scroll region uses measured header and visible-dock bounds (`--workspace-top` and `--workspace-bottom`). Hiding the dock releases that space for reading; revealing it reserves space again. The dock sits above the handle so pointer activation cannot accidentally select an app underneath. Luke remains present and may overlap content, as authorized by the user. Expanded windows cannot be dragged away from viewport edges. Enlarged-text reflow and room exploration keep ordinary chrome visible.

The per-window Arrange button and placement popover are removed. Compact desktop windows can still be moved by their title/handle with pointer dragging or keyboard arrows. The dock utility is now **Explore Vision Pro**. Clear view reveals the room and keeps Luke visible; returning through the dock restores a full-size app.

Initial full-viewport verification covered all seven dock destinations, Step into my work, Meet the human, both project satellites, loaded case-study content, Home expand/restore, mobile restore, Luke's dialog, and Explore Vision Pro/Clear view/return. Those checks predated the collapsed chrome refinement.

The chrome refinement was checked at 1280×720, 1024×768, 390×844, and 844×390: compact Home, island disclosure/Luke, keyboard reveal/Escape, pointer reveal/dismissal, navigation selection, restore, room exploration/return, and case-study navigation. No horizontal page overflow appeared. The desktop dock measures 86px high, down from 112px (23%); landscape navigation retains its existing compact sizing. Production-controller regressions cover hover crossing, mouse versus touch pinning, focus recovery, room controls, island/Luke dismissal, and enlarged-text reflow.

Welcome audio is attempted once per document, with no automatic late click retries. Initialization now also covers modules loaded after DOMContentLoaded while readyState is still `interactive`; the production-wiring regression test covers loading/interactive/complete states under both success and autoplay refusal. Native browser testing again confirmed `NotAllowedError` on a fresh visit, followed by full 1.9-second playback from the explicit sound button and no repeated sound from navigation. Website code cannot override the browser's no-gesture audible-autoplay restriction. Sources: [WebKit autoplay policy](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/), [HTMLMediaElement.play](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play).

Landscape verification caught and fixed a conflict with the prior short-viewport page-flow dock. Full-size landscape now uses compact fixed chrome, leaving a scrollable safe reading area (139px tall at 844×390 and 83px at 667×375). Extremely short or enlarged-text viewports use normal flow rather than an unusable fixed-height pane.
